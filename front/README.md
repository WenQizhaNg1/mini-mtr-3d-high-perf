# 前端与工作台

在根目录运行 `npm --prefix front run dev`，默认 http://127.0.0.1:8080 。首页为 /，工作台为 /workbench。

## 接入操作

1. 在根目录 .env 配置 WORKBENCH_TOKEN，启动后端。工作台输入同一令牌；令牌仅驻留页面内存。
2. 数据集页导入 GeoJSON、CSV 或 WKT，明确 WGS84 坐标和来源唯一键。通用数据发布后可加入样式。
3. “绘制数据”创建点或线；“编辑要素”选择完整要素，拖动控制点或修改坐标和属性。“更新文件”按来源键合并或替换。
4. “交通接入”选择运营方、时区、路径和站点数据集，映射线路编号、颜色、站点编号与名称。
5. 添加有向方案，选择源路径、方向及停站顺序。自动投影存在歧义时填写 0–1 沿线比例。
6. 选择 Adapter，导入时刻表 CSV 或填写发车规则，保存并重算。错误显示对应方案、站点或字段。
7. 首页选择运营方、模拟或实时模式。模拟支持时间轴、暂停和倍速；实时展示来源实际提供的位置与到站预测。

实时中断不自动切换模拟。ETA-only 数据没有可跟随车辆；GPS 或里程观测有稳定车辆身份后可选中跟随。过期观测单独标识。

## 样式与生命周期

业务分组展开后保留多个原生显示部分。metadata.role 决定路线层位置、车站选择和车辆来源绑定。修改普通样式控件保留表达式，复杂表达式通过高级 JSON 修改。保存后读取服务端结果，离开时检查未保存草稿。

首页按所选运营方时区切换日夜样式（06:00–18:00 日间）。当前首页样式键沿用 mtr-light / mtr-dark，同一套样式可显示其他运营方。切换样式保留相机、跟随与选中状态，车辆几何尺寸仍由渲染代码控制。

运营方和模式切换取消旧请求与订阅；暂停回放保留独立的数据变更订阅。数据保存后刷新路径和车辆。页面卸载关闭所有订阅、请求、定时器和动画。

工作台预览中的车辆是示意要素。底图文件、账户权限和数据集整体删除仍由部署与管理流程处理；页面支持单个要素删除和运营方解除绑定。

## 部署与验证

开发环境 /api 代理至 Java 3002，可用 API_PROXY_TARGET 覆盖。首页读取地址可用 VITE_TRAIN_API_URL 覆盖；工作台始终使用同源 /api。生产环境为页面设置 index.html 回退，并独立代理 API。瓦片、字体与精灵地址来自后端 MARTIN_PUBLIC_URL。

`npm --prefix front test` 运行样式、时区测试；`npm --prefix front run build` 做类型检查和打包。
`npm --prefix front run test:browser` 使用本机 Chrome，后端需要已有 V1，测试管理令牌为 integration-only。实际端到端用例默认请求 3003，可用 API_PROXY_TARGET 指定独立测试实例；测试会创建 ui-* 数据集与运营方。
