# 实时列车连续推演

2026-09-05 实施。针对原先“覆盖整趟 delay 后重新计算位置”造成的跳变，实时状态移到 TypeScript；计划回放保持无状态 SQL 查询。

## 数据流

`港铁 ETA → 来源时间去重 → 持续关联 → 重排未来节点 → 带时间的沿线短段 → MapLibre`

- `domain/motion.ts` 保存每趟内部推演 ID、米制轨道进度、到站/发车节点和最后接受的观测。ID 来自模拟班次，不代表真实车辆编号。
- 首次关联使用同线路、方向、终点和预计到站时间；后续优先延续已有关联。窗口 120 秒，同级候选差距不足 20 秒时拒绝分配，按计划监测站顺序避免一轮内交叉关联。
- 使用上游 `curr_time`，重复、倒序、超过 180 秒的观测不更新状态；无来源时间不强行使用本地接收时间替代。
- ETA 更新以更新时刻旧轨迹的位置为新起点，仅调整到目标站前的未来运行时间，保留停站时长和后续区间用时。超过线路配置速度上限、倒退或不可达到站时间的观测标记冲突，保留旧轨迹。
- 未观测班次按计划推演。目标站 ETA 尚未达到且观测超时的列车最多预测到最后观测后 180 秒，随后冻结并标记 stale。新观测从冻结位置续接。
- 如果目标 ETA 在观测有效窗口内已经达到，监测站之后沿校准后的剩余行程继续预测，标记 predicted，终点退出。单监测站不能确认下游实际位置，不能把此阶段称为持续实时定位。

## 存储与生命周期

- `db/motion-queries.ts` 读取轨道和运行窗口内的计划节点。几何在启动时加载，班次窗口每分钟补充；4326 几何 fraction 转为沿线米制距离。
- `motion_checkpoint` 是唯一新增表。保存轨迹、原计划、关联和观测去重时间；观测处理后、每 10 秒和正常退出时保存，写入串行化。
- 启动按同 ID、同路线和相同计划恢复一天以内的检查点；超期或计划不兼容时重新初始化。近期检查点恢复的是时间函数，不是旧坐标快照。它不是历史事件归档。
- 数据库 advisory lock 强制同一数据库只有一个实时推演实例。退出等待轮询和快照任务，再保存、释放所有权。
- 正常运行到终点后退出且不重复加入；已超出计划结束两小时且不再进入加载窗口的状态被清理。丢失观测的冻结状态不无限积累。
- `0003_equal_steve_rogers.sql` 新增检查点并使 `train_positions(at)` 不再读取 `realtime_offsets`。旧偏移表和历史维护兼容代码保留，本轮没有整理或删除其他表。
- 更换运行中的路网后需重启实时服务以重新加载几何；在线热换路网不在本轮范围。

## 前端协议

实时 TrainPosition 增加 `estimate` 和 `motion`，其余接口与字段保留。`motion` 是未来最多 3 秒的位置时间点，含途经的所有轨道顶点和停站节点；直接发送小片段，不要求前端加载整条轨道。

前端用约 1 秒缓冲按服务端时钟播放，保留更新点之前的缓冲轨迹，仅替换未来。倒序快照丢弃。超过预测终点停止外推；快照间隔超过 3 秒时显式重建播放时间基准，不补画断线期间未知的路程，重新定位仍可能可见。

该实现解决 ETA 修订导致的运行位置不连续；不保证真实车辆身份，也不保证任意断网、无可用检查点重启或数据重建后的显示无缝。

## 验证

- 合成回归覆盖 ±30/120 秒 ETA、不可达 ETA、歧义匹配、重复观测、过期冻结及续接、弯道、停站、终点退出、检查点恢复和监测站之后的预测。
- `test/fixtures/twl-mok-eta.json` 保存港铁旺角站两次真实公开响应；数据库集成测试用真实 OSM 轨道验证更新前后位置相同、后续速度有界、序列化恢复一致。
- 数据库事务测试验证修改旧偏移不影响相同时间的计划回放；前端测试验证轨迹转弯、预测期限及倒序快照。
- 本地实时接口一次约 55 秒采样含 52 个不同快照、49 次预计时间偏移变化；未检出一秒数百米跳变，最大观测速度约 31.8 米/秒。这是有限样本验证，不是对所有运行情况的证明。
